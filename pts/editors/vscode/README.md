# ParallelScript for VS Code

Editor support for [ParallelScript](https://github.com/bcwongaa/parallelscript) `.pts` files:

- **Highlighting.** TypeScript's grammar, with `parallel` highlighted as a keyword wherever the compiler reads it as one: `parallel f(x)` and `parallel for (…)`. Where `parallel` is a name, such as `parallel(f(x))`, `const parallel = …` or a line that ends in `parallel`, it is shown as a name.
- **The language server.** The extension starts `pts lsp --stdio`, typescript-go's language server running on the program the compiler sees: its prelude (`int`, `u8`, …, `parallel`), the `pts:` modules, and ParallelScript's own errors (the numeric rules, the guardrail, features left out) next to tsc's. Completions, hovers, go to definition, references, rename, code actions, formatting, inlay hints and semantic highlighting come from it.
- **Library files.** Go to definition on `range`, `Channel` or an array's `map` opens the library file it is in (`ptslib:///parallel.pts`, `ptslib:///sync.pts`, `bundled:///libs/lib.es5.d.ts`) read-only; the server supplies the text.

## Requirements

A `pts` binary. Build one from the repository root with `make build` (it is `pts-bin/pts`), then either put it on `PATH` or set `parallelscript.server.path` to it. The language server needs nothing else: no `PTS_HOME`, Node or tsconfig.json.

## Install

Build the package and install it, from the repository root:

```sh
make vscode                                                   # tests, then pts/editors/vscode/dist/parallelscript.vsix
code --install-extension pts/editors/vscode/dist/parallelscript.vsix
```

Or, in VS Code, run **Extensions: Install from VSIX…** and pick the file. VS Code 1.91 or later.

## Settings and commands

| Setting | Default | What it does |
|---|---|---|
| `parallelscript.server.path` | `pts` | The `pts` binary: a command on `PATH`, an absolute path, `~/…`, or a path relative to the first workspace folder (such as `pts-bin/pts` in the ParallelScript repository) |
| `parallelscript.trace.server` | `off` | `messages` or `verbose` logs the messages between VS Code and the server in the **ParallelScript** output channel |

**ParallelScript: Restart Language Server** restarts the server, as does changing `parallelscript.server.path`. Formatting, inlay hint and other editor preferences are read from the `typescript.*` and `js/ts.*` settings, as for TypeScript files.

## Known limits

- Errors that only code generation finds, mostly "PTS1001 … isn't supported yet", show up when you build, not in the editor.
- The server reports itself as typescript-go's (`serverInfo`).

## Development

```sh
npm ci
npm test          # type-checks the extension, generates the grammar and tests it with vscode-textmate
npm run package   # builds dist/extension.js and dist/parallelscript.vsix
```

`syntaxes/ParallelScript.tmLanguage.json` is generated by `scripts/grammar.mjs` from VS Code's TypeScript grammar (`syntaxes/TypeScript.tmLanguage.json`, vendored unchanged): change the script, not the output. `test/parallel_samples.json` lists where `parallel` is and isn't the keyword; the grammar's test and the parser's (`pts/lsp/grammar_test.go`) both check it, so the highlighting follows the parser.
