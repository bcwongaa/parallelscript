## Known issues

- **Corpus programs skipped** (D-089): 47 of the 300 in `pts/tests/corpus/` diverge from Node; each says why in its `// skip:` line (4 are by design, the rest are single causes).
- **A method with a default can't provide a required parameter of an interface method:** `class Sq { label(suffix = "sq") }` used as `interface { label(suffix: string): string }` is PTS1001: the method takes `(string, given)` and the interface's table entry passes `(string)`. Arrows drop the flag when their context always passes the argument (D-055); methods would need the method-table entry (or an object literal method's field) to pass `true`.
- **Equality narrowing loses an integer type to tsc:** after `if (b === 5)` with `b: u8`, tsc types `b` in the branch as the literal `5`, so `[b + 1]` is a `number[]` to tsc while the semantic pass computes `b + 1` as a `u8` (the value is converted to number; nothing breaks). Fixing it means `replacePrimitivesWithLiterals` (`internal/checker/flow.go`) keeping D-048's types; not worth a fork edit yet.
- **An await inside an expression-bodied async arrow, not first in it, is PTS1001** with the message about loop conditions and default values: `async () => (await p) + 1` (and so `parallel((async () => (await p) + 1)())`); a block body (`{ const v = await p; return v + 1; }`) works. The hoisting of D-111 works on statements, and an expression body has none; lowering it as `return <expr>;` would fix it.
- **Parallel gaps (D-121):** a loop busy with something referenced (a long timer, a server) doesn't take tasks queued on others until it runs dry. (The rejection race and async generators driven from two loops were fixed by D-143.)
- **Shared generators and iterators (D-143):** threads racing on one sync generator get `TypeError: Generator is already running` from the losing resume, and threads racing on a generator or a runtime iterator may skip or repeat items (memory-safe; use `pts:sync` to share one).
- **Overrides must keep the overridden method's parameter types** (PTS1001 otherwise; D-028): an override may leave out trailing parameters or return a subclass's instance (D-091), but not change a parameter's type or leave out one with a default. A base constructor that calls an overridden method reading a subclass field sees `""` or 0 for a string or number field, where Node sees `undefined`, since the subclass's initialisers run after `super()` returns (an object field is undefined, D-141); `console.log(this)` there lists the subclass's fields too, where Node doesn't yet.
- **Unset fields of object types (D-141):** a class's field of an object type read before the constructor sets it is undefined: tests of truth, `=== undefined`, `== null`, `??=` and `??` with a value of its type, boxing and member reads behave as in Node, but a use as an object elsewhere (an argument, a builtin method's receiver) throws its own TypeError rather than Node's, `typeof` says "object", `?.` throws, and `??` with a value of another type keeps it (`run/unset_fields_differences.pts`). A string or number field reads `""` or 0 meanwhile.
- **An erased copy makes instances of generic classes for `any`** (D-078): code whose type parameters are erased (a generic function value passed on generically, a nested generic arrow function, a dispatched generic method, D-101) makes `Box<any>` for a `new Box(x)`, and converting that to `Box<number>` throws `TypeError: Expected Box, got Box` (one corpus program, `oop/result_option.pts`: `Some.map` dispatched through its erased copy). Calls of module-scope generic consts are monomorphized since D-102. Fixes: name instances in checks' messages (`Box<number>`) at least; dispatch generic methods by a per-class switch over monomorphized instances.
- **A class's method that lies about a type parameter through `any` throws where Node goes on:** `id(x: any): any { return ["c", x]; }` implementing an interface's `id<T>(x: T): T` and called as `i.id(5)` throws `TypeError: Expected number, got Array` (the result is checked against the call's `number`). By design (D-L09), listed so it isn't mistaken for a bug.
- **Yields left out by D-111:** a yield in a loop's condition or update, a case label, a later variable of a declaration, a default value or an optional chain is PTS1001 (`pts/tests/errors/yield_positions.pts`). Since D-145 operands before a hoisted yield or await keep their values, except a compound assignment's target read through a getter or `any` (`o.total += yield v` with a getter reads after the yield) and a method looked up on an object (`o.m(yield v)` finds `m` after it).
- **A `#line` path is absolute, but stack frames can show a relative one:** built as `pts build dir/p.pts` from elsewhere, frames show `dir/p.pts`; built in the file's own directory, the absolute path (Node always shows absolute file URLs).
- **Indexing a non-ASCII string is O(n)** (a scan from the start); ASCII strings are O(1). A lazy UTF-16 index needs a GC-traced field in `pts_string` (D-016): M2.1 or M8.
- **Integer constant expressions wrap at run time** instead of failing to compile: `const b: u8 = 200 + 56` is 0 (D-012). A literal operand of `as` is a `number`, so `9007199254740993 as int` is 9007199254740992; annotate instead (`const x: int = 9007199254740993` is exact).
- **Upstream, pre-existing:** `go test ./internal/execute/tsctests/ -run TestTscCommandline/tsc/show_help_with_ExitStatus.DiagnosticsPresent_OutputsSkipped` fails at the fork base too (verified with the PTS edits stashed). The help header's padding depends on the real version string, which changed on the 7.1 nightly branch after the baseline was written. Not ours; CI excludes it (M0.7).

- **RegExp gaps (D-132, D-133, D-134):** console.log of matchAll's iterator prints `Object [Array Iterator] {}`; replacement callbacks with default parameter values or with a pattern that may be a string are PTS1001; a group that took no part in a match, passed to a typed callback of the match array's methods (`m.map(f)`, `m.filter(f)`) or met by `for…of`, throws `TypeError: Expected string, got undefined (group n of the match took no part in it)` where JS passes undefined; a named group that took no part is undefined in `groups` but `RangeError` where a string is required; the `d` flag gives no `indices`; without `u`, `.` and classes match an astral character whole (JS sees two units); no `v` flag; `\s` misses U+FEFF.
- **An object literal with getters as an `IteratorResult` is PTS1001** (D-146): `next(): IteratorResult<number> { return { get done() {…}, get value() {…} }; }` can't convert the literal to the union's shapes; results typed `any` work.
- **A method read through `any` has `length` 0** (D-144): the bound value's descriptor has no parameter count; typed reads count as D-098 says.
- **Publication of new objects relies on x86's store order** (D-130): fresh objects are published by plain or relaxed stores, which x86-64 never reorders with the stores that filled them; an ARM port needs release stores where they are published. Generated code's plain one-word field and element accesses rely on clang's x86-64 code rather than ISO C (the shared-memory contract, `docs/ARCHITECTURE.md` §4.13, D-143).
