# Owner answers and orchestrator rulings

## 2026-10-12: rulings on the independent review (`docs/reviews/2026-10-12-gpt-6.1-sol/REVIEW.md`)

The owner was asked about the first four items and did not reply within the hour. Their standing instruction is: "if I don't respond in time, continue on your judgement". So these rulings were made by the orchestrator with the owner's authority. Apply them in M6.0c and log each one as a D-entry citing this file.

1. **Extra `parallel` restriction (review finding 9, D-120): remove it.** `parallel` followed by any expression, including a function or class expression (`await parallel function () { return 42; }`), is accepted as the operator, typed as `Promise<Awaited<T>>`. The single guardrail from brief §2.6 remains the only parallel-specific check (owner: no Rust-style strictness).
2. **`.par.reduce` with a non-identity initial value (review finding 9): match the sequential result.** `xs.par.reduce(f, init)` must equal `xs.reduce(f, init)` for every associative `f`, whether or not `init` is an identity: fold each leaf from its own first element, combine the leaf results, apply `init` exactly once at the front, and return `init` for an empty input. Document that `f` must be associative (brief §2.6); don't require an identity. Tie-breaker: simple and correct beats a documented trap.
3. **`Object.freeze` (D-105): enforce it.** Writing to a frozen object's field, element or hash-map key throws `TypeError` (Node's message, as in strict mode and ES modules). `Object.isFrozen` stays as it is. If a check on every write measurably costs more than about 2% on the benchmarks, use a frozen flag in the object header and a check on the slow paths only, but writes must never silently succeed.
4. **Out-of-range reads (D-015, D-038, D-089, D-090): keep the current design.** It stays a documented difference (SPEC §8): such a read gives `undefined` wherever the context can hold it, and throws `RangeError` where a non-optional `T` is required. Don't rework it into `T | undefined` everywhere. Do improve the error message to suggest `?? default`, `noUncheckedIndexedAccess`-style typing, or an explicit length check.
5. **State machines in the C emitter (D-109): defer to M8.** It works and it's tested; move the transform into an IR pass in M8, when escape analysis needs it anyway. Record it as a known divergence from brief §2.3 in `docs/FORK.md` or `SPEC.md`'s implementation notes. For M6.0b, the review's finding 6 (snapshotting values read before a suspension) is fixed in place.
6. **Generic erasure (D-051, D-078, D-079, D-101): keep erasure as a fallback, but fix what it breaks.** Erasure is fine for function values that are passed around generically. A value that an erased copy constructs and then converts back to a specialized type must work: dispatch to the monomorphized instance, or construct a specialized instance when the type arguments are known at the call site. `Expected Box, got Box` must disappear (M6.0b).
7. **Checked copies when converting from `any` (D-071, D-072) and adapter identity (D-075): keep them, documented.** They're the price of making `any` honest (brief §2.4). Make sure SPEC §8 lists them in one "identity and aliasing" table.
8. **Interface merging (D-020): keep it.** Interfaces merging with interfaces changes nothing at run time, and it's ubiquitous in real TypeScript.
9. **Asserted union literals unchecked (D-104): add the check if it's cheap.** Otherwise leave it as a Known issue. It's not memory-unsafe as long as the extraction itself is checked, which M6.0a covers.
10. **Shared-memory contract:** a racy program may read stale values, but never torn values, crashes or out-of-bounds accesses (brief §2.5). That rules out non-atomic multi-word copies of numbers that another thread can read. M6.0a owns this.
