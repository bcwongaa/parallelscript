## Causes and fix

All in D-176. C01: `compoundAssignment` sent every keyed place to `recordElementOrSet`, which asserts a hash-map type, but a dynamic place has a key too. C21: `nullishAssignment` returned the current value for any type that wasn't a union, null or undefined, so `any` never stored; `recordFallback` tested only bool, number, string and union entries; compound assignments read entries with `MapGetChecked` even where D-172 reads a missing one as undefined. C19: `recordKey` rejected dynamic keys. C22: the logical assignments' value had the place's type, not tsc's. C24: `pts_dynamic_set` stored a converted copy but returned the original value.

The slice took three iterations, each driven by executed evidence: the first narrowed results without a check; the independent review showed that segfaulting on `&&=` of a variable without a value and printing a double's bits for keyed `||=` ([h02-review.md](h02-review.md), round 1). The second converted with checks, and the review's round 2 showed a statement `x &&= v;` throwing where JS doesn't and untyped `new Array()`/`new Map()` on keyed elements losing pushes or throwing. The final version skips conversions of values nothing uses and gives such values the place's type.

## Boundaries kept

- D-072's copies stay: a separate reference to a right side that was converted still holds the original (`const fresh: T[] = []; rec[k] = fresh; fresh.push(x)` in erased code leaves the entry empty; Node shares), and a type-guarded `unknown` read as a typed array is a copy, so `(raw.list ??= new Array()).push(x)` pushes onto a copy as `raw.list!.push(x)` does (scratch `j1.pts`). SPEC §8's identity table now says that a write's value is the copy stored.
- An object literal reached through `any` keeps its fixed layout and property types (D-L10, D-072): `o.a ??= 1` on `{ a: null }` throws the same TypeError as `o.a = 1` (`logical_assign_any_checks.pts`).
- `r.missing &&= v` on a typed `Record<string, number>` still throws D-059's RangeError (only `any` entries and entries holding undefined read undefined).
- A value outside the place's type (a variable or union field without a value, D-141) makes a used `&&=` value throw a checked TypeError where Node goes on with undefined; an unset union field already read as an object on the base (scratch `h2.pts`). Statements don't throw.
- An `any` key is converted to a string once, before the right side; V8 converts at each get and set, which only a key with a side-effecting `toString` can tell.
- Honest PTS1001s remain for an untyped `new Map()`'s value used as `Map<any, any>` (passed on, `forEach`, a value of another type in `.set`), for a typed array kept where tsc says `any[]` (D-094), and for unions of several object members with `new Map()`; `{} as Record<K, …>` for literal-union `K` is C23 (H29).
- Not tested here: `.par` tasks, symbol keys, `Proxy`. Suspensions on the right side are C25 (H08).
