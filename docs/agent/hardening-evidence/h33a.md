## Reproducer
The `reproducer` (isolated worktree of `37a9ce909`; [report](h33a-reproducer.md)) wrote `pts/tests/https_test.go` (a lab of about 45 Go TLS and plain servers with throwaway CAs, made at test time, servers that must not verify recording any request that reaches them), `http/fetch_tls.pts` (differential), `fetch_tls_parallel.pts` (pts only: aborts, `.par.map` and `parallel`, descriptors and memory after 1,000 requests), `fetch_tls_one.pts` (trust store, public site), and Node's oracle (Node 24.21.0, undici 7.29.1, OpenSSL 3.5.8; six identical runs). It found that a cross-origin redirect kept `authorization` and `cookie` (pre-existing over plain HTTP; with TLS an https→http redirect would leak them in cleartext), and that Node's name rules differ from mbedTLS's: Node falls back to the common name when there are only IP addresses, takes partial wildcards and rejects `*.localhost`; Node reports expiry over trust and `INVALID_PURPOSE` for a non-CA issuer.

## Implementation
`tls.c` (sessions over buffers, the trust store, `on_verify` with a port of Node's `checkServerIdentity`, `verify_failure`), `fetch.c` (`start_secure`, `advance_secure`, `send_sealed`), `pts_coded_error_new`, `http.pts` (https allowed; credentials dropped across origins), the toolchain's `mbedtlsLibrary`. After the oracle the parent moved the name check from mbedTLS's to Node's rules, ordered the chain errors as OpenSSL's last error (validity, purpose, trust), added the refused-issuer case, and adopted the OpenSSL/Go trust-store convention the reproducer's tests encode (an explicit `SSL_CERT_FILE` still reads the usual directories). Two test edits, both a choice the reproducer left open (its report: "If you'd rather not emit it, strip it in the program and change `nodeCAHint`"): the programs strip Node 24's `; if the root CA is installed locally, try running Node.js with --use-system-ca` advice from the cause's message, and the recorded oracle and the trust-store test's expected line lose it; ParallelScript doesn't print advice about Node's flag (D-223). Two existing tests pinned the old rejection and change with the behaviour: `run/fetch_local.pts`'s `https` case (a fixed port 59999, "not supported yet") becomes `https refused` at the test's closed port, Node's `connect ECONNREFUSED`; `docs/examples/guide_fetch.pts` fetched `https://example.com/`, which would now need the network, and shows `ftp://`'s `unknown scheme` instead.
