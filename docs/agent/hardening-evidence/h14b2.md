## Unshipped candidate policy and implementation

The archived candidate's `serve({ requestTimeout })` uses **milliseconds**, default **300000**, finite integer **0..2147483647**; 0 disables it, omission/undefined chooses the default, invalid numeric values throw option-specific RangeError before binding. The first request clock starts at HTTP adoption or successful HTTPS handshake, alongside headers. A later request starts at its first bytes only after preceding queued output drains. Header and request budgets are absolute and the earlier active one wins. Complete headers remove only the header budget; body bytes and `100 Continue` never refresh or end the request budget. A fully received request stops the clock before handler dispatch, so slow handlers and queued answers are excluded. Expiry closes without a handler or final response; an earlier interim `100 Continue` may already have been sent. This is explicit ParallelScript policy, **not Node timeout parity**, despite the same default number.

One connection-owned libuv timer continues to represent the earlier active absolute nanosecond timestamp. The original request deadline is retained across header completion; timer starts/rearms round remaining milliseconds upward and callbacks preserve H14a's monotonic early-callback check. Existing detached asynchronous timer/TCP close ownership is unchanged. A buffered follower already parsed into an incomplete body while preceding output was queued receives a request-only timer once that output drains. Shutdown and shared chunk parsing are unchanged. The H36 handoff fixture has only the new native ABI argument; it remains a Linux surrogate, not independent/native-Mac acceptance.
