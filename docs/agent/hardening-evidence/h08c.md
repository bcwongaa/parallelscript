## The fix

D-189 has the design. In short:

- `pts/cgen/arrays.go`: `arrayCall` hands `ArraySpread` to `spread`, which writes each operand inline as a statement that appends it (`pts_array_append` of a same-typed array, `_as_read` where holes read undefined, or `pts_array_push` of an element) before the next operand is evaluated; `concat` (`a.concat`) keeps evaluating all operands first; both use `appended`.
- `pts/cgen/cgen.go`: `callBuiltin` runs `copyChangedSpreads` for console methods and dynamic calls with spreads: a `SpreadArg` followed by an argument that may write (`effectsOf`), whose array the argument doesn't make itself (`isNewArray`), is written by `spreadCopy` as a copy taken where it is evaluated (`pts_array_copy`, or `pts_value_to_array` for `ValueSpreadItems`); `spreadArgs` panics on a console spread that isn't an array (console.c reads them as arrays).
- `pts/lower/dynamic.go`: `dynamicCallWith` lowers spreads with `dynamicSpread`: an IR array as it is, anything else as `ValueSpreadItems(box(x), text)`.
- `pts/ir/ir.go`: `ValueSpreadItems` (`pts_value_spread_items`); `SpreadArg`'s and `ArraySpread`'s comments.
- `pts/runtime/src/dynamic_methods.c`, `pts.h`: `pts_value_spread_items` (an array, tuple or typed array as it is; otherwise `pts_value_iterable`'s new array, D-078's TypeError for a non-iterable); `pts_value_to_array` allocates its result at its final length (`pts_array_of_length`) and writes its slots.
- Tests: `run/spread_elements_read_before_later_arguments.pts` unskipped and extended by the reproducer (9 lines: `xs.values()`, `?? []`, a readonly view, `string[]`, objects, a hole filled later, `length = 0`, console of `values()`, a replaced variable); the reproducer's `run/any_call_spreads_iterables.pts` (C153) and `run/spreads_read_before_later_operands_at_every_site.pts` (C152 at every site); the parent's `run/any_and_console_spreads_read_at_their_place.pts` (review round 1's gaps a–e); the C unit test above.
- No upstream package touched.

### Round 1 (snapshot `/tmp/h08c/snap1`)

Verdict **ready**, no correctness bug or output regression. Dispositions, each re-run by the parent:

- **F1 (medium, perf): fixed.** A spread through `any` of an array, tuple or typed array went through `pts_value_to_array`, which grew its result one element at a time: `q_any` 2.35× the base. `pts_value_to_array` now allocates at its final length, and `ValueSpreadItems` hands an array, tuple or typed array to the runtime as it is, copied only when a later argument may write (`spreadCopy`). Table above.
- **F2 (low): fixed.** `copyChangedSpreads` no longer copies an array the argument makes itself (`isNewArray`). H08b's kept copy is still copied once more before a later writer (rare; D-189's known gaps). The empty first array that `appended` copies predates H08c.
- **F3 (pre-existing): recorded** (C168 → H22). Verified by the parent on the base (`side/k_method_getter.pts`).
- **F4 (info): recorded** (C167 → H22). V8's message differs with the call site and tier; the tests pin the error's name only.
- **F5 (pre-existing): recorded** (C166 → H29; the reproducer's S4).
- **Tests (a)–(e): done** in `run/any_and_console_spreads_read_at_their_place.pts` (a generator drained at the spread; a function union's callee with a set; a hole filled later through `any` and console; a callee found before an await with a later writer; `console.error`, `warn` and `assert` with `// stderr:` lines).
