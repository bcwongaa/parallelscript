## Design
Bun 1.4.3 (`~/.bun/bin/bun`, parent probe `bun/probe.ts`) takes `tls: { certFile, keyFile }` (paths) and `tls: { cert, key }` (PEM text); `tls: {}` serves plain HTTP; a cert without a key listens as https and fails every handshake; bad PEM throws `ERR_OSSL_PEM_NO_START_LINE`; a missing file `TypeError: Unable to access certFile path`; `server.protocol` says `https`. D-224 takes Bun's names, refuses a `tls` without both parts, and throws Node's fs errors and mbedTLS's descriptions.

mbedTLS's key objects: an EC key's base-point multiplication uses the static comb tables of `MBEDTLS_ECP_FIXED_POINT_OPTIM` (on by default, `ecp_curves.c`'s `ecp_group_load`), so it writes no shared state, but an RSA key's private operations take its lock, so a key shared by the loops would serialize their handshakes. Each listener gets an identity of its own (measured below).

## Reproducer
The `reproducer` (isolated worktree of `8fe8a7b1e`; [report](h33b-reproducer.md)) wrote `pts/tests/https_server_test.go` (five tests, certificates, keys and CAs made at test time), `http/server_tls.pts`, `every_loop_tls.pts`, `lifecycle_tls.pts`, `fetch_self_tls.pts`, `serve_tls_options.pts`, `errors/serve_tls_options.pts` and a README paragraph, and checked them against a stand-in server on the same vendored mbedTLS, a Go TLS proxy in front of the plain server, Bun 1.4.3 and Node 24. It found C348 (IPv6 URLs without brackets, pre-existing) and settled the contract's open points as the implementation has them (a client's close_notify alone is a departure, `tls: {}` names the certificate first, option errors before bind errors, a passphrase for an unencrypted key ignored, mid-handshake connections idle for `stop()`, a chain with an unparsable certificate refused).

## Implementation
`tls.c` (`pts_tls_identity_new`, `pts_tls_server`, `pts_tls_close`, `pts_tls_forget`, PSA's start-up shared), `http.c` (identities per listener before binding, files read with Node's errors, `unseal`/`end_sealed`/`seal`/`send_sealed`/`close_idle`, the per-thread read buffer), `pts.h` (`pts_http_listen` takes `tls`), `http.pts` (`TLSOptions`, `ServeOptions.tls`, `Server.protocol`, `tlsParts`). First GREEN run (`green1.log`): three failures, two of them one bug: UBSan's `applying zero offset to null pointer` in `consume` (http.c:556), since `process` ran on a connection whose buffer was still NULL during its handshake; fixed by reserving the buffer in `unseal` before the first read. The third, `TestHTTPSServerOptions`, came from C349 (below), not from serve.

One test edit: `serve_tls_options.pts`'s `describe` tested `error instanceof TypeError` on the caught value cast to `NodeJS.ErrnoException`, which C349 (a pre-existing compiler bug: `instanceof` through an interface that extends Error is false) makes false; it now tests `e instanceof TypeError` on the caught value itself, which checks the same contract (the thrown value is a TypeError) without the unrelated bug. C349 has its own skipped RED test, `run/instanceof_error_interfaces.pts` (Node: `true true true true` / `true true`; pts: `false false false true` / `false false`; the base the same).
