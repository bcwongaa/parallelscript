## The fix

D-194 has the design. In short:

- `pts/lower/forwarding.go` (new): forwarders (`forwarder`, `addForwarder`, `forwardingInstance`, `valueForward`, `methodForward`, `objectMethodForward*`), the instantiating adapter (`instantiatingAdapter`, `instantiatingAdapterSkipping`, `adaptedExpression`), the take-back (`tentatively`, `failedSince`, `takeBack`, `quietly`), helpers (`genericSignature`, `takesAs`, `fromErasedTo`).
- `pts/lower/instances.go`: `erasedValue.forward`; `specialize`, `reaches`, `specializeValue` for forwarders; `keyedInstanceCall` (`namedInstanceCall` with several names and `ByKey`); `passedAsIs`'s `typedPrimitive` (C205); `erasedArguments` passes a rest parameter on as its array.
- `pts/lower/generics.go`: `genericMethodValue`, `boundGenericMethod`, `genericMethodOf` (dispatched values by name, C208/C209; forwarders); `calledOnlyName`.
- `pts/lower/methods.go`: `boundMethod` takes a forwarder; `bind` of generic values forwards; `call`/`apply`/`bind` of a class's generic method (`isGenericInstanceMethod`, `runsOnThisArg`, `mayUseThis`, `usesObject`, `usesSuper`; C210).
- `pts/lower/closures.go`: `adapt` and `functionAsMethod` instantiate; `adaptSkipping` takes a forwarder. `callbacks.go`, `promises.go`: generic callbacks instantiate. `destructuring.go`: class methods destructure (C211), object types' generic methods forward. `element_calls.go`: `keyedCall` (C196). `yield_expressions.go`: `namesMethods`. `lower.go`: `keyedCall` in `call`.
- `pts/ir` (`ir.go`, `walk.go`, `print.go`): `InstanceCall.ByKey`. `pts/cgen` (`classes.go`, `order.go`): the keyed lookup. `pts/runtime` (`object.c`, `pts.h`): `pts_method_instance_find_keyed`; `tests/object_test.c`: `method_instances_are_found_by_a_keys_name`.
- Tests: new `run/generic_method_values_passed_on.pts`, `generic_method_values_destructured.pts`, `generic_method_values_parameters.pts`, `generic_dispatched_method_values.pts`, `generic_bound_values.pts`, `generic_method_call_bind_this.pts`, `generic_values_nongeneric_contexts.pts`, `generic_value_instantiations.pts`, `generic_element_access_runtime_keys.pts`, `generic_method_calls_yield_arguments.pts` (against Node), `generic_value_forms_any_boundaries.pts`, `generic_values_keep_other_instances.pts` (no-diff); `generic_method_factories.pts` unskipped; `generic_call_forms_any_boundaries.pts`'s last line (its honest parameter key now matches Node and is covered by the keyed test; the line now names no method, which still throws); `lower_test.go`'s `TestWrappersOfGenericValuesForwardTheirInstances`. ## Costs

- **Generated C:** unchanged for programs that read no generic method as a value, bind none and give no generic value to a non-generic function type: of the 1,030 test programs, only the new tests and three existing ones change (≤ 1.4%). Where they do, each wrapper pairs with each demand of its erased type, as declarations already did (C172): review round 1's `s_60` (60 method values, each to its own consumer) 10,461 → 93,741 lines, build 1.4 → 32.9 s, 113 → 607 MB on an idle host; 60 declarations so passed make 43,942 lines (7.4 s) on both trees (`growth.txt`). emit-c of `s_60` 1.8 s; the rest is clang.
- **Run time:** a method value's or bound value's typed call is one more lookup (the forwarding instance's by-name or value lookup) where it called the erased copy and checked its result; a generic value in a non-generic context is an adapter around an instance lookup per call; a keyed call's lookup is uncached (3M calls: 153–343 ms keyed against 78–125 ms dotted, round 1's `perf/`, a noisy host). No other code changes.
