## Implementation and conservative contracts

`nested_container_sources.go` builds bounded syntax trees using the existing literal member/key whitelist. `container_sources.go` flattens a complete static access path to one root, validates the complete root/alias component and walks direct literal children to a terminal. Every root use must traverse intermediate literals without extracting them; unsafe uses of unselected children poison even a plain terminal sibling. No positive tree is published before all syntax, contract and use checks finish. Cached unknowns remain unknown; no provisional alias entry is visible.

Nested positives initially require inferred, uncontextualized trees outside generic lexical contexts. Shared trees use raw checker APIs, never substitution-dependent `typeAt`, `contextualType` or `literalType` summaries. Fresh identities may differ only along finite direct literal-child syntax edges: propagate actual target property/element contracts downward; require complete equal required data keys on both own/target object sides; forbid method/accessor/optional/call/construct/index contracts. Nonliteral callable/object terminals require exact raw checker contracts. Both array contracts must be ordinary arrays of the same generic target (not mutable versus readonly/tuple), with no uncertain common element union/intersection/any/unknown. No structural assignability or recursive checker-graph equivalence is introduced. Contextual/generic/uncertain layouts stay unknown.

Existing **128 depth / 4,096 work / 256 sources** limits remain. Sibling work does not accumulate depth; a 140-sibling shallow tree stays provable. Function/receiver expression/return caches and active sets remain separate; the shared tree cache stores no per-instance positive source summary.
